# 01 — Yacht model (`src/yacht-threejs.html`)

A single self-contained HTML page that builds a wooden gaff-rigged yacht procedurally in three.js r128. No external models, no build step, no loaders. Everything — hull, deck, spars, sails, rigging, fittings, stand and shelf — is generated in code from a handful of parametric curves.

---

## 1. Running and dependencies

- Open the file in any modern browser with WebGL 1+.
- The only external resource is `https://cdnjs.cloudflare.com/ajax/libs/three.js/r128/three.min.js` (UMD build, exposes `window.THREE`).
- If the script fails to load, the HUD text is replaced with an error message and nothing else runs.
- r128 is used because it is available as a single UMD script on cdnjs, which keeps the page a one-file drop-in. It already uses BufferGeometry only (the legacy `THREE.Geometry` was removed in r125). Upgrading: UMD builds were deprecated in r150 and removed in r160, so newer versions need ES-module imports; and the colour API changed — `renderer.outputEncoding = THREE.sRGBEncoding` becomes `renderer.outputColorSpace = THREE.SRGBColorSpace`, `texture.encoding` becomes `texture.colorSpace`. Lighting intensities also changed with physically-correct lights becoming default in r155, so expect to retune light values.

## 2. Coordinate system and units

| Axis | Direction |
|---|---|
| `+x` | towards the bow |
| `-x` | towards the stern |
| `+y` | up |
| `+z` | starboard (right side when facing the bow) |
| `-z` | port |

Units are arbitrary but proportioned like metres at roughly 1:1 of a 10 m yacht. The hull length `L = 10`, so the stern (transom) plane sits at `x = -L/2 = -5` and the stem converges to `z = 0` at `x = +5`.

**Viewing from astern.** A viewer standing at `x < -5` and looking towards `+x` has `+z` on their right. This matters for the transom text: letters are laid out with increasing `z` from left to right. Derivation: for a camera looking along world `+x` with up `+y`, the camera's local `-z` maps to world `+x`, so local `z` is world `-x`; local `x = y × z = ŷ × (−x̂) = +ẑ`. Local `+x` is screen-right, so screen-right is world `+z`.

```
scene
├── HemisphereLight   (warm sky 0xffe4b8, brown ground 0x3a2410, 0.55)
├── DirectionalLight  "sun" (0xffe0b0, 1.15) at (12,16,10), casts shadows, 2048² map

│   ├── center        — everything lying in the centreline plane z = 0
│   ├── stbd          — the starboard half, the only side modelled by hand
│   ├── <mirror of stbd> — generated by mirrorZ(stbd), the port half
│   └── nameGroup     — transom letters and their ghosts (NOT mirrored)

```

The split into `center` / `stbd` / mirror is the backbone of the model's symmetry (section 6). `nameGroup` is attached directly to `yacht` after mirroring so the text is never reversed.

## 4. Materials and procedural textures

All surfaces use `MeshStandardMaterial` except rigging (`LineBasicMaterial`).

`plankTexture(base, seam, plankW)` draws a 256×256 canvas: a flat base colour, a 2 px darker seam every `plankW` px, and six random 1 px semi-transparent grain lines per plank. The texture is `RepeatWrapping` in both axes and tagged `sRGBEncoding`. Because grain is random, every reload looks slightly different.

| Key | Colour | Notes |
|---|---|---|
| `lightWood` | `0xb17d47` | barrel |
| `spar` | `0x8d6438` | mast, boom, gaff, rails, frames |
| `deckHouse` | `0xc39a66` | cabin walls |
| `dark` | `0x2c1d12` | keel, rudder, door, cleats |
| `sail` | `0xe6dcc4` + plank texture `#e7ddc6/#d5c9ad/22` | `DoubleSide`, roughness 0.95 — reads as canvas with seams |

| `glass` | `0x1a2530` | cabin windows |

| `transom` | `0x3b2717`, `DoubleSide` | flat stern plate |

`sh(mesh)` sets `castShadow` and `receiveShadow` on anything it wraps; almost every mesh goes through it.

## 5. Hull

### 5.1 Parametric curves

The hull is a loft along a normalised length parameter `u ∈ [0, 1]` where `u = 0` is the transom and `u = 1` the stem. World `x = (u − 0.5) · L`.

```
Bmax = 1.55    maximum half-beam
D    = 1.05    maximum draft below y = 0
H    = 0.95    base freeboard

beam(u)  = u > 0.45
           ? Bmax · (max(0, 1 − ((u − 0.45)/0.55)²))^0.62      // bow: tapers to 0 at u = 1
           : Bmax · (1 − 0.36 · ((0.45 − u)/0.45)²)            // stern: tapers to 0.64·Bmax at u = 0

depth(u) = D · (0.32 + 0.68 · sin(πu)^0.6)                     // deepest amidships, 0.32·D at ends

sheer(u) = H · (1 + 0.55·u² + 0.28·(1 − u)³)                   // sheer line: rises strongly to the bow,
                                                               // slightly to the stern
deckY(u) = sheer(u) − 0.32                                     // deck sits 0.32 below the rail
```

Key values:

| `u` | `beam` | `depth` | `sheer` | meaning |
|---|---|---|---|---|
| 0.00 | 0.992 | 0.336 | 1.216 | transom |
| 0.45 | 1.550 | ~1.02 | ~1.07 | maximum beam |
| 1.00 | 0.000 | 0.336 | 1.473 | stem |

The `0.62` exponent on the bow gives a fuller entry than a pure ellipse; the `0.6` exponent on depth flattens the bottom amidships; the cubic stern term in `sheer` gives the slight upsweep aft visible on the reference photo.

### 5.2 Section shape

Each station `u` is a half-section swept by `th ∈ [0, π/2]`:

```
z = beam(u) · cos(th)                     // th = 0 → at the rail, th = π/2 → on the centreline
y = sheer(u) − (sheer(u) + depth(u)) · sin(th)^0.72
```

The `0.72` exponent produces slack bilges and a slightly hollow garboard. At `th = π/2`, `z` is forced to exactly `0` (not `≈ 6e-17`) so both halves share bit-identical seam vertices.

Resolution: `NU = 48` stations × `NT = 16` segments per half-section → 49 × 17 = 833 vertices, 1 536 triangles per half.

### 5.3 Vertex-colour bands

Colours are assigned per vertex by absolute height, mimicking the painted strakes of the reference:

| Condition | Colour | Band |
|---|---|---|
| `y < 0.02` | `0x2e1f14` | antifouling / bottom |
| `y > h − 0.36` | `0x3b2717` | dark sheer strake + bulwark |
| `h − 0.55 < y < h − 0.47` | `0x8a5a30` | decorative stripe |
| `y < 0.2` | `0x8a5a30` | boot-top |
| otherwise | `0xb27d48` | light topsides |

Because colours are per vertex, band edges are interpolated across one triangle row. Raising `NT` sharpens them.

### 5.4 Winding and normals — `orient()` and `seamNormals()`

The first published version had the triangle winding reversed: the computed face normals pointed inward, so the outside of the hull was back-facing and parts of the interior showed through. This is why the port side "looked modelled differently".

`orient(geom, probeIndex, outward)` fixes this robustly instead of relying on getting the index order right by hand:

1. `computeVertexNormals()`.
2. Read the normal at a probe vertex whose true outward direction is known — station `NU/2` (midships), `j = 0` (at the rail), expected outward `(0, 0, +1)`.
3. If the dot product is negative, swap indices 0 and 2 of every triangle and recompute normals.

`seamNormals(geom)` then zeroes the `z` component of every vertex normal where `|z| < 1e-6` and renormalises. Without it, normals on the keel line are averaged only from one side, and after mirroring the two halves meet at a visible light/dark crease.

### 5.5 Inner bulwark shell

The same half-hull geometry is reused with `hullIn` (`BackSide`), scaled `(1, 1, 0.94)` and shifted `y −0.005`. Seen from above the deck, this is the inside face of the bulwark; seen from outside it is hidden behind the real hull. Scale in `x` was originally `0.995`, which left a 2.5 cm gap in front of the transom — fixed to `1.0`.

### 5.6 Transom

A triangle fan in the plane `x = −L/2`. Vertex 0 is the **top centreline point** `(−L/2, sheer(0), 0)`; vertices 1…NT+1 follow the stern section outline from the rail down to the keel.

**Bug history.** The fan originally started at the mid-height point `(−L/2, (h0 − d0)/2, 0)`. Its first edge then ran diagonally from mid-height to the rail corner, while the true top edge of the transom is horizontal (the sheer is constant across `z`). The triangle between the mid-height point, the rail corner and the top centreline point was never filled — the "triangle with a hole" visible from astern. Starting the fan at the top centreline point makes its two boundary edges coincide with the real edges (top rail and centreline), so the fan covers the whole half-plate.

The transom uses `DoubleSide`, so its winding does not matter.

### 5.7 Deck

A strip of `NU` quads per half from `z = 0` to `z = 0.945 · beam(u)` at height `deckY(u)`. UVs: `u·3` along the length, `0 → 1` across, so planks run fore-and-aft. The 5.5 % inset leaves room for the bulwark; the inner shell closes the gap visually.

### 5.8 Rails

- Side rail: a `TubeGeometry` (radius 0.045, 64 segments, 6 radial) along a Catmull-Rom curve through `((u−0.5)L, sheer(u)+0.03, 0.985·beam(u))`. Starboard only; mirrored.
- Stern rail: a cylinder of length `1.97 · beam(0)` lying along `z` at the transom top, on the centreline group. Closes the two side rails aft.

The old version built the port rail by `geometry.scale(1, 1, −1)`, which silently flips winding and inverts shading — one of the original asymmetry sources. Now nothing is ever negatively scaled.

## 6. Symmetry: modelling one half, mirroring the other

### 6.1 Rule

Everything either lies on the centreline (goes into `center`) or is modelled once on starboard (`z ≥ 0`, goes into `stbd`). The port side is never written by hand; it is `mirrorZ(stbd)`.

| `center` | `stbd` (→ mirrored) |
|---|---|
| keel, rudder, tiller, stern rail | half hull, inner shell, half transom, half deck, side rail |
| bowsprit, stem block | shrouds (3), bowsprit shroud, ratlines |
| mast, topmast, truck, crosstrees | jib sheet |
| boom, gaff | cabin windows + frames (3) |
| all sails | lantern, barrel, cleat |
| forestay, inner stay, bobstay, backstay, peak halyard, mainsheet, leech line | |
| deckhouse, roof, skylight, door, fore hatch, capstan | |
| steering wheel, spokes, pedestal | |

The door was moved from `z = 0.35` to `z = 0` because mirroring would have produced two doors.

### 6.2 `mirrorZ(object)` — math

Reflection across the `z = 0` plane is `S = diag(1, 1, −1)`. For a point `p` in an object with rotation `R` and translation `t`, world position is `w = R·p + t`. The mirrored world point is:

```
S·w = S·R·p + S·t
    = (S·R·S)·(S·p) + S·t        since S·S = I
    =   R'   ·  p'  +  t'
```

So the mirrored object needs:

- **geometry** `p' = S·p` → negate `position.z` for every vertex;
- **translation** `t' = S·t` → `(x, y, −z)`;
- **rotation** `R' = S·R·S` → for a unit quaternion `(x, y, z, w)` this is `(−x, −y, z, w)`.

Check: a rotation about `z` commutes with `S` and must stay unchanged — `(0, 0, s, c) → (0, 0, s, c)` ✓. A rotation about `x` by `θ` must become a rotation by `−θ` — `(s, 0, 0, c) → (−s, 0, 0, c)` ✓.

- **normals** transform like positions under a reflection → negate `normal.z`;
- **winding** — a reflection has determinant −1, which flips the apparent orientation of every triangle; swap indices 0 and 2 of each triangle so front faces stay front faces.

Scale is copied unchanged. `castShadow`, `receiveShadow` and `visible` are copied. The function recurses into children and supports `Mesh`, `Line` and plain `Group`. Materials are shared, geometries are cloned.

Limitation: non-indexed meshes would need vertex reordering instead of index swapping. Every geometry in the scene is indexed (Box, Cylinder, Sphere, Torus, Tube, custom), so this path is not implemented.

### 6.3 Why not `group.scale.z = −1`?

It works for positions and three.js corrects normals via the inverse-transpose normal matrix, but backface culling uses screen-space winding, which a negative determinant flips. You then need `DoubleSide` everywhere, which doubles fill cost and breaks the `BackSide` inner-shell trick. Baking the reflection into cloned geometry avoids all of it.

## 7. Spars

`sparBetween(a, b, r1, r2, mat)` builds a `CylinderGeometry(r1, r2, |b−a|)` (radius `r1` at the `+y` end, `r2` at `−y`), places it at the midpoint, and orients it with `quaternion.setFromUnitVectors((0,1,0), normalize(b − a))`.

## 8. Sails

### 8.1 Geometry

`sailMesh(P0, P1, P2, P3, bulge, segs = 18)` builds a bilinear patch. For `a, b ∈ [0, 1]`:

```
left  = lerp(P0, P1, b)          // luff: tack → head
right = lerp(P3, P2, b)          // leech: clew → peak
p     = lerp(left, right, a)
p.z  += bulge · sin(πa) · sin(πb)^0.7
```

`sin(πa)` is zero at luff and leech, so the sail stays attached to its spars and stays; `sin(πb)^0.7` keeps the belly low and full rather than symmetric. Triangular sails pass `P1 = P2` (head = peak).

UVs are `(4a, 4b)` to repeat the canvas-seam texture.

### 8.2 Table

| Sail | Tack `P0` | Head `P1` | Peak `P2` | Clew `P3` | Bulge | z-offset |
|---|---|---|---|---|---|---|
| Gaff main | `(0.86, 2.15, 0)` | `(0.86, 8.4, 0)` | `(−4.15, 10.1, 0)` | `(−5.7, 2.1, 0)` | 0.90 | 0.00 |
| Jib | `(7.45, bowY+0.35, 0)` | `(0.9, 9.7, 0)` | = head | `(1.1, 2.0, 0)` | 0.75 | 0.12 |
| Staysail | `(5.0, sheer(1)+0.1, 0)` | `(0.9, 7.4, 0)` | = head | `(1.6, 1.95, 0)` | 0.55 | 0.06 |

All bellies are towards `+z`: the boat is on one tack. This is physically correct and intentionally breaks visual symmetry. The small `z`-offsets separate overlapping sails near the mast to prevent z-fighting.

### 8.3 Controls

- "Показывать паруса" toggles `sails.visible`.
- "Плоские паруса" calls `buildSails(false)`: disposes the old geometries and rebuilds with zero bulge. Offsets are kept.

## 9. Rigging

All rigging is `THREE.Line` with a 1 px dark brown `LineBasicMaterial`. WebGL ignores `linewidth > 1` on most platforms, so thickness cannot be controlled this way — see Known limitations.

Centreline: forestay (masthead → bowsprit end), inner stay (`y 7.5` → stem), bobstay (bowsprit end → stem at waterline), backstay (topmast → transom), peak halyard (gaff end → topmast), mainsheet (boom end → deck), leech line (gaff end → boom end; outlines the mainsail's trailing edge).

Starboard (mirrored): three shrouds from `(0.7, 9.9, 0)` to chainplates at `u = 0.45, 0.53, 0.62` on the rail; one bowsprit shroud; jib sheet from the jib clew to the deck; ratlines every 0.55 from `y = 2.5` to `7.0`, each spanning between the middle shroud (chainplate at `u = 0.53`) and the aft one (`u = 0.45`), with `z` linearly interpolated from the chainplate towards the mast as height increases. The forward shroud has no ratlines.

## 11. Transom name (current, v1 mechanic)

**Status:** this is the first, simple version. The richer animation (nails, swing, rivets) lives only in `letter-anim-debug.html`. See `03-integration-plan.md`.

- Six letters `ПОБЕДА`, each a `PlaneGeometry(0.248, 0.31)` with its own 128×128 canvas texture: bold serif at 104 px, 8 px dark outline `#3a2412`, gold fill `#d8ab3c`. Material: `transparent`, `alphaTest 0.35`, `DoubleSide`, metalness 0.45.
- Placement: `x = −L/2 − 0.03`, `y = 0.72`, `z = (i − 2.5) · 0.27`, rotated `y = −π/2` so they face astern. At `y = 0.72` the transom half-width is ≈ 0.97, so the outer letter edges at `|z| ≈ 0.81` fit with margin.
- Each letter has a "ghost" behind it: same glyph in weathered wood `#6b4a2e`, opacity 0.55, shown once the letter is knocked off.
- **Knocking:** a click (pointer moved < 5 px between down and up) or a tap (< 8 px) raycasts against the letter meshes. A hit gives the letter velocity `(−0.6…−1.1, 0.5…1.0, ±0.3)` and random spin; it falls under `g = 9.8`, and on reaching the shelf top (`y = −1.78`) is laid flat with a random rotation.
- "Отколоть «ПО»" knocks letters 0 and 1 with a 240 ms stagger. "Прибить обратно" restores all.

Known shortcut in v1: the plane is the full 128² canvas, so the glyph only occupies its centre. Any pivot placed on the plane's corners would float outside the letter. The debug stand solves this by cropping (see `02-letter-animation.md`, §3).

## 13. Camera and input

A hand-rolled orbit camera (OrbitControls isn't in the UMD core):

```
camera.position = target + r · (sin φ · sin θ,  cos φ,  sin φ · cos θ)
target = (0.4, 3.6, 0);   home: θ 0.62, φ 1.22, r 23
```

| Input | Effect |
|---|---|
| mouse drag | `θ −= dx·0.006`, `φ −= dy·0.006`, `φ` clamped to `[0.15, 1.55]` |
| wheel | `r *= 1 + deltaY·0.001`, clamped `[8, 50]` |
| one-finger drag | as mouse, factor 0.007 |
| two-finger pinch | `r *= previousDistance / currentDistance` |
| "Вид с кормы" | `θ = −π/2, φ = 1.35, r = 22` |
| "Сбросить камеру" | home |

Autorotate adds `0.25 rad/s` to `θ`. Any drag or touch turns it off and unticks the checkbox. `prefers-reduced-motion: reduce` disables it at start.

## 14. Rendering

- `antialias: true`, pixel ratio capped at 2.
- Shadows: `PCFSoftShadowMap`, sun shadow camera ±14, bias `−0.0006`.
- `outputEncoding = sRGBEncoding`; canvas textures tagged sRGB.
- Background and fog colour read from the CSS variable `--bg`, updated on `prefers-color-scheme` change. Fog from 30 to 70.
- `setAnimationLoop` with `dt` clamped to 50 ms so a backgrounded tab does not produce a huge step on return.

## 16. Known limitations

- **Line width.** Rigging is always 1 px. For thicker ropes swap to thin `TubeGeometry` (costly at ~40 lines) or `Line2`/`LineMaterial` from three's examples (needs extra script files).
- **Sails cast shadows from one side only** in terms of self-shadowing artefacts; with `DoubleSide` and soft shadows some acne may appear at grazing sun angles. Tune `shadow.bias` if the sun moves.
- **Random grain.** `plankTexture` uses `Math.random()`, so screenshots differ between reloads. Seed it if you need reproducible renders.
- **Font dependency.** Letters use the system serif. On machines without Georgia the fallback changes glyph shapes, which in the debug stand also moves the snapped fixing points.
- **No LOD / instancing.** Fine for a single model (≈ 150 draw calls); not suitable for a harbour of 50 yachts without merging geometries or instancing (see tactic 06).
- **Transom letters (v1)** are not glyph-cropped and have no fixings.

## 17. Extension points

- **Export.** Load `GLTFExporter` from `examples/js/exporters/GLTFExporter.js` (r128 UMD) and export `yacht` to `.glb`. Canvas textures export as embedded PNG.
- **Parametric variants.** Every proportion is a constant or a small function. For procedurally generated yachts (tactic 06) wrap construction in `buildYacht(params)` returning the group, seed the palette and sail bellies from a hash of the project name.
- **Module extraction.** The file is an IIFE; to reuse in a Next.js app, move helpers (`sparBetween`, `orient`, `seamNormals`, `mirrorZ`, `sailMesh`) into an ES module and import three as a package. Replace the UMD tag and `window.THREE` guard.
