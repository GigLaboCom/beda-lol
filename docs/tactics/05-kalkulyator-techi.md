# 05 — «Калькулятор течи»

**Пять ползунков про твой проект — и ты видишь уровень воды в трюме и сколько недель осталось до того, как яхта ляжет на дно.**

## Зачем

Одноразовый, быстрый, наглядный. Слабее квиза как шутка, но сильнее как «зеркало»: человек сам вводит свои цифры и видит результат, с которым трудно спорить. Хорошо работает как иллюстрация к постам про соотношение кода и продвижения.

## Механика

### Входные параметры

| Ползунок | Диапазон | Смысл |
|---|---|---|
| Часов в неделю на код | 0–60 | |
| Часов в неделю на маркетинг | 0–30 | |
| Недель с начала проекта | 1–104 | |
| Реальных пользователей сейчас | 0–1000 (лог-шкала) | |
| Недель с последнего нового пользователя | 0–52 | |

### Модель

Модель шуточная и **должна быть показана пользователю целиком** — прозрачная формула честнее, чем «наш алгоритм посчитал», и сама по себе становится предметом обсуждения. Черновик:

```
share   = code / (code + marketing + 1)                  // доля кода, +1 чтобы не делить на ноль
leak    = share² · 10                                     // пробоин в неделю, квадрат — чтобы 90/10 было сильно хуже 70/30
pump    = marketing · 0.8 + log2(users + 1) · 1.5         // насос: маркетинг и уже имеющиеся люди
drought = min(silence_weeks, 26) · 0.6                    // тишина без новых людей — отдельная течь

net     = leak + drought − pump                           // вёдер в неделю
water   = clamp(net · weeks / 600, 0, 1)                  // уровень воды: 0 — сухо, 1 — по палубу
sink_in = net > 0 ? ceil((1 − water) · 600 / net) : ∞     // недель до затопления
skew    = share < 0.3                                     // отдельный флаг перекоса в маркетинг
```

Коэффициенты подбираются так, чтобы типичные случаи давали ожидаемые ощущения. Проверка по формуле выше (проекту 20 недель):

| Кейс | net | Уровень | До дна |
|---|---|---|---|
| 40 ч кода, 0 маркетинга, 0 пользователей, 20 недель тишины | ≈ +21,5 | ≈ 72% | ≈ 8 недель |
| 20/10, 50 пользователей, 1 неделя тишины | ≈ −11,7 | сухо | — |
| 5/20, 0 пользователей, 4 недели тишины | ≈ −13,2 | сухо, но `skew` → подпись «насос работает, а корпуса нет» | — |

Перед запуском прогнать таблицу из 20–30 кейсов и подстроить коэффициенты. Это не прогноз, это аргумент для разговора — так и написать на странице.

### Визуализация

- Разрез яхты сбоку: вода поднимается внутри корпуса по мере движения ползунков, в реальном времени.
- При `water > 0.7` яхта начинает оседать (смещение по `y`) и слегка крениться.
- При `water = 1` — вода переливается через палубу, буквы на транце начинают по одной отваливаться (движок из стенда).
- Цифра «недель до дна» крупно, моноширинным.

## Результаты

| Состояние | Подпись |
|---|---|
| сухо | «Трюм сухой. Редкость — сделай скриншот» |
| до 30% | «Подтекает. Пара вёдер в неделю — и всё под контролем» |
| 30–70% | «Воды по колено. Насос нужен уже на этой неделе» |
| 70–99% | «Палуба мокрая. {sink_in} недель до дна» |
| 100% | «Лежим на дне. Проект есть, судна нет» |
| перекос в маркетинг | «Насос мощный, но качать нечего» |

К каждому — одна ссылка: на «Осмотр» (01), чтобы понять, какой насос чинить, или на трекер (03).

## Шеринг

- Картинка: разрез с водой + «{sink_in} недель до дна» + пять цифр.
- Ссылка с параметрами в адресе: `/tech?c=40&m=0&w=20&u=0&s=20`.

## Использование в рубрике

- Пост-сравнение: «одна и та же яхта при 40/0 и при 30/10» — две картинки рядом.
- Разбор формулы: почему доля кода в квадрате, почему тишина — отдельная течь. Люди любят спорить с формулами, это вовлечение в комментариях.
- Поправки к модели от аудитории — повод для следующего поста («вы предложили, я поменял коэффициент»).

## Данные

Не обязательно. Для сводок — анонимно параметры и результат.

## Техническая реализация

- Проще всего без 3D: 2D-разрез корпуса на SVG, вода — прямоугольник с `clip-path` по контуру корпуса. Так быстрее и легче на мобильных.
- 3D-вариант: тот же корпус, камера сбоку, плоскость воды внутри через `clippingPlanes` материала корпуса или полупрозрачный бокс, обрезанный по сечению.
- Все расчёты на клиенте, мгновенно.

## Метрики

- Время на странице и число изменений ползунков (играют ли).
- Шеринг.
- Переходы в 01 и 03.

## Риски

- **Кажется научным.** Лечится показом формулы и прямой подписью «шуточная модель».
- **Люди со здоровым балансом получают скучный результат.** Для «сухо» нужен такой же смешной текст, как для «на дне».

## MVP → расширения

**MVP:** SVG-разрез, пять ползунков, формула на странице, шеринг ссылкой.
**Потом:** 3D, отваливание букв при затоплении, сравнение двух конфигураций рядом.

## Трудоёмкость

1–3 дня. Основное время — подбор коэффициентов и текстов, а не код.
