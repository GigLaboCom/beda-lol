# JSON-LD reference for beda.lol

Adapted from `cloud-agents/docs/ld-jsons/PROMPT-GENERATE-LDJSON.md`. Same method: rendered page, then source, then summary, then schema. The difference is the output: TypeScript objects in Astro components, not YAML frontmatter.

## Site facts

| | ru (default, unprefixed) | en (`/en/…`) |
| --- | --- | --- |
| Site name | `t('site.name')` | `t('site.name')` |
| `inLanguage` | `htmlLang.ru` → `ru` | `htmlLang.en` → `en` |
| Home URL | `new URL('/', Astro.site)` | `new URL('/en', Astro.site)` |

- Publisher: `{ '@type': 'Organization', name: t('site.name'), url: <home for lang> }`. That is the rubric itself, and there is no separate company entity.
- Author of pillar articles: a `Person`. `PillarArticle.astro` currently inlines the name. Keep the same person on all articles. If you touch it, consider moving the name to `ui.ts`.
- Logo, if a schema needs one: an icon from `apps/web/public/` (generated by `@beda/brand`, e.g. `android-chrome-512x512.png`). Absolute URL.
- Images: prefer the prebuilt OG cards (`/og/bukvy/<slug>.png`, `/og/osmotr/<code>.png`, 1200×630). The en pages reuse the Russian cards on purpose (see memory: i18n images on hold).

## Type decision tree

Choose by what the page **is**, and only add what the page visibly supports.

| Page kind | Type(s) | Notes |
| --- | --- | --- |
| Home `/`, `/en` | `WebSite` | `name`, `alternateName: 'beda.lol'`, `url`, `description`, `inLanguage`. Add `publisher` only if it is also used elsewhere. No `SearchAction`, because the site has no search. |
| Pillar article `/bukvy/<slug>` (ru) | `Article` + `BreadcrumbList` in one `@graph` | `headline` (≤ 110 chars), `description`, `image`, `author`, `publisher`, `mainEntityOfPage`, `url`, `inLanguage`. Add `datePublished` / `dateModified` only from real data, such as a frontmatter date. Never invent one. |
| Pillar article (en stub) | `BreadcrumbList` only | The article is not translated, so claiming an `Article` in English would be false. |
| Index / hub (`/bukvy`, future `/treugolnik` hubs) | `BreadcrumbList`; optionally `CollectionPage` + `ItemList` of the children | `ItemList` only lists pages that are indexable. |
| Interactive tool (`/osmotr` quiz, `/kak-nazovesh`) | `BreadcrumbList`; optionally `WebApplication` (`applicationCategory: 'GameApplication'` or `'BusinessApplication'`, `offers.price: '0'`, `operatingSystem: 'Any'`) | Google shows no rich result for these, so it's low value. Add only if asked. schema.org `Quiz` is meant for educational assessments, so don't use it for a joke inspection. |
| Quiz result `/osmotr/r/<code>` | none | `noindex` and disallowed in robots.txt. |
| UGC epitaph (S27) | `CreativeWork` + `BreadcrumbList` | `name`, `text` (plain), `dateCreated`, `author` as `{ '@type': 'Person', name }` only if the author chose a public name; `isAccessibleForFree: true`. User links never go in `sameAs`. |
| Registry yacht (S30) | `CreativeWork` or `SoftwareApplication` (if the project is software) + `BreadcrumbList` | Only fields the author supplied and moderation approved. |
| 404, `/dev/*` | none | Out of search. |

Avoid:
- `FAQPage`: since 2023 Google shows FAQ rich results only for authoritative government and health sites. Add it only if a page has a real visible FAQ block and the user wants it anyway.
- `HowTo`: rich results were removed in 2023. The "first nails" lists in pillars are body text, not a HowTo.
- `Product`, `Review` and `AggregateRating`: nothing on the site is for sale or rated, so these would be fabricated.
- `VideoObject`: only if a page actually embeds a video.

## Field rules

**URLs.** Always use `new URL(getLocalizedPath(path, lang), Astro.site).href`. This makes them absolute and locale-prefixed, with no trailing slash. External URLs (`sameAs` to the rubric's channels) come from `ui.ts`; skip any value where `isPlaceholder(value)` is true.

**Breadcrumbs.** They mirror the visible `<nav class="crumbs">` when there is one, otherwise the URL depth. The first is the site home (`t('site.name')`). Every item has `item`, including the last, which equals the canonical (Google accepts an `item` on the last element, and the existing pages include it). Use the `breadcrumbList()` helper for the plain case.

**Text.** Use the exact strings the page shows, from `t()` or the content entry. Plain text only: strip Markdown and HTML. Don't paraphrase or add keywords that are not on the page.

**Dates.** ISO 8601 with a timezone (`2026-09-28T00:00:00+02:00` or `…Z`). Take them only from data the build has (frontmatter, DB timestamps). `dateModified >= datePublished`.

**Drafts / noindex.** A `noindex` page may still carry JSON-LD, which is harmless and ready for when it is published. Don't emit different JSON-LD for draft and published pages; the `robots` meta already handles that.

**Escaping.** `JsonLd.astro` replaces `<` with `<`, so user text cannot close the script tag. Always render through it and never with `set:html` directly. It is a data block (`type="application/ld+json"`), so the CSP from S14 does not need a hash for it.

**One page, one graph.** If you need two or more nodes, use a single `@graph` and don't emit several `<JsonLd>` tags. Don't use more than one node of the same type (the audit flags a duplicate `WebSite`, `Article` or `BreadcrumbList`).

## Content summary template

```markdown
## JSON-LD summary: <route>

- Locales: ru <url> · en <url>
- Component: apps/web/src/components/pages/<Name>.astro (routes: pages/<…>.astro, pages/en/<…>.astro)
- Indexable: ru yes/no (robots=…), en yes/no
- Visible content → fields:
  - h1 "<exact>" → headline / name   (source: t('<key>') | entry.data.title)
  - lead "<exact>" → description     (source: …)
  - crumbs: <A> / <B> / <C>          → BreadcrumbList
  - image: <og:image>                → image
  - dates shown / available: <none | frontmatter field>
- Existing JSON-LD: <types or none>
- Proposed: <types> (ru) · <types> (en)
- Why: <one line>
- Left out: <field — reason>
```

## Example: pillar article (current shape)

```astro
---
const url = new URL(getLocalizedPath(pillarPath(slug), lang), Astro.site).href;
const home = new URL(getLocalizedPath('/', lang), Astro.site).href;
const index = new URL(getLocalizedPath('/bukvy', lang), Astro.site).href;

const graph: Record<string, unknown>[] = [
  {
    '@type': 'BreadcrumbList',
    itemListElement: [
      { '@type': 'ListItem', position: 1, name: t('site.name'), item: home },
      { '@type': 'ListItem', position: 2, name: t('letters.title'), item: index },
      { '@type': 'ListItem', position: 3, name: `${letter} — ${pillarName}`, item: url },
    ],
  },
];
if (!isEn) {
  graph.unshift({
    '@type': 'Article',
    headline: title,
    description: lead,
    inLanguage: htmlLang[lang],
    mainEntityOfPage: url,
    url,
    author: { '@type': 'Person', name: '…' },
    publisher: { '@type': 'Organization', name: t('site.name'), url: home },
    image: new URL(`/og/bukvy/${slug}.png`, Astro.site).href,
  });
}
const jsonLd = { '@context': 'https://schema.org', '@graph': graph };
---
<Fragment slot="head"><JsonLd data={jsonLd} /></Fragment>
```

## Example: plain breadcrumbs

```astro
---
import { breadcrumbList } from '../../lib/jsonld';
const crumbs = breadcrumbList(Astro.site, [
  { name: t('site.name'), path: getLocalizedPath('/', lang) },
  { name: t('nav.osmotr'), path: getLocalizedPath('/osmotr', lang) },
]);
---
<JsonLd slot="head" data={crumbs} />
```

## Validation checklist

General
- [ ] The rendered page was read (build output or curl) for every locale before writing
- [ ] The types match what the page is (see the tree), with nothing the page does not show
- [ ] All URLs are absolute, from `Astro.site` + `getLocalizedPath`, and have no trailing slash
- [ ] The last breadcrumb is the canonical, and positions start at 1 and are contiguous
- [ ] Dates are real and ISO 8601, and there are none if no data exists
- [ ] Exactly one `<JsonLd>` per page, with one `@graph` for several nodes

Locale
- [ ] `inLanguage` is `htmlLang[lang]`
- [ ] Strings come from `t()` or the content entry, and new keys are added for both `ru` and `en`
- [ ] An en stub page claims no content type it does not have

Repo
- [ ] `audit-ldjson.mjs` shows 0 errors and every warning is explained
- [ ] `task check` passes
- [ ] No cartoon references in any field
